# CatalogMonitor_SpaceDebris

Система каталогизации и мониторинга космического мусора.

## 1. Описание системы

Центр каталогизации и мониторинга космического мусора осуществляет наблюдение за космическими объектами и фрагментами на орбите с целью ведения каталога и предупреждения опасных сближений.

Каждый наблюдаемый объект характеризуется:
- уникальным каталожным номером;
- международным идентификатором;
- типом (действующий спутник / выведенный из эксплуатации аппарат / фрагмент / ступень ракеты);
- размерной оценкой;
- текущими орбитальными элементами;
- статусом (каталогизирован / утерян / повторно обнаружен).

Наблюдения выполняются наземными средствами (радиолокаторы, оптические телескопы, лазерные дальномеры). На основе прогнозов движения рассчитываются опасные сближения, формируются уведомления владельцам спутников.

## 2. Исходные требования к системе

### 2.1. Сущности (объекты учёта)

1. **Космический объект** — каталожный номер, международный идентификатор, тип, размерная оценка, орбитальные элементы, статус, дата последнего наблюдения.
2. **Средство наблюдения** — идентификатор, тип, зона обзора, чувствительность, режим работы, статус.
3. **Сеанс наблюдения** — дата/время, средство, объект, полученные данные, результат обработки.
4. **Прогноз движения** — объект, орбитальные элементы, горизонт прогноза, дата расчёта.
5. **Опасное сближение** — время, минимальное расстояние, вероятность столкновения, вовлечённые объекты, статус.
6. **Уведомление владельцу спутника** — сближение, владелец, рекомендации, дата отправки, реакция владельца.
7. **Журнал обслуживания средств** — средство, период простоя, причина, количество потерянных сеансов.
8. **Владелец спутника** — наименование, контакты, список спутников.

### 2.2. Процессы

- Регистрация объекта в каталоге
- Проведение наблюдения
- Обработка результатов наблюдения
- Расчёт прогноза движения
- Присвоение статуса «утерян» / повторное обнаружение
- Расчёт опасных сближений
- Формирование уведомления владельцу
- Фиксация реакции владельца
- Плановое обслуживание / регистрация отказа средства
- Составление расписания наблюдений
- Формирование отчётности

### 2.3. Роли пользователей и права доступа

| Роль | Права |
|------|-------|
| Оператор наблюдения | Вносит данные наблюдения, правит свои необработанные записи, просматривает свои данные и каталог |
| Аналитик орбитального движения | Создаёт прогнозы, расчёты сближений, обновляет орбитальные элементы, просматривает весь каталог |
| Специалист по уведомлениям | Создаёт уведомления, редактирует статусы и реакции, просматривает сближения |
| Инженер по обслуживанию средств | Создаёт записи об обслуживании/отказах, обновляет статус средств |
| Владелец спутника | Подтверждает реакцию на уведомление, просматривает только свои уведомления и сближения |
| Руководитель центра | Создаёт расписания, редактирует любые данные, удаляет, формирует отчёты, просматривает всё |
| Администратор системы | Управляет учётными записями, правами, справочниками |

### 2.4. Правила и ограничения

- Уникальный каталожный номер и международный идентификатор обязательны
- Тип объекта ограничен: действующий спутник / выведенный / фрагмент / ступень ракеты
- Статус «утерян» присваивается автоматически при превышении срока отсутствия наблюдений
- Снятие статуса «утерян» только при повторном обнаружении (сохраняется прежний номер)
- Уведомление формируется только при превышении порога вероятности столкновения
- Реакция владельца: «манёвр выполнен» / «отказ» / «не подтверждено»
- Порядок: наблюдение → обновление элементов → прогноз → сближение → уведомление → реакция
- Отчёт формирует только руководитель центра
- ... (полный список правил из отчёта)

### 2.5. Отчётность

Отчёт формируется руководителем центра за период и содержит:

| № | Показатель | Тип | Единица |
|---|------------|-----|---------|
| 1 | Количество каталогизированных объектов по типам | int | целое |
| 2 | Количество опасных сближений за период | int | целое |
| 3 | Доля утерянных объектов | float | 0..1 |
| 4 | Доля повторно обнаруженных объектов | float | 0..1 |
| 5 | Охват орбитального пространства | float | 0..1 / % / км³ |
| 6 | Среднее время между наблюдениями | float | часы |

## 4. Архитектура (Model–View–Controller)

Система разделена на три слоя:

| Слой | Ответственность | Что не делает |
|------|-----------------|---------------|
| **Model** | Сущности, валидация, расчёты, правила статусов, права ролей | Не вводит и не выводит данные, не знает о меню |
| **View** | Меню, формы, списки, отчёты, сообщения об ошибках | Не вызывает бизнес-логику, не проверяет права |
| **Controller** | Главный цикл, текущий пользователь, вызов сервисов Model, передача результата во View | Не содержит формул и бизнес-правил |

### Взаимодействие слоёв

- Controller → Model: через сервисы (`Сервис_каталога`, `Сервис_наблюдений`, `Сервис_анализа` и т.д.)
- Model → хранилище: через `Интерфейс_хранилища<T>`
- Controller → View: команды «покажи список», «запроси форму», «покажи ошибку»
- View → Controller: возвращаемые значения методов ввода

Диаграмма классов UML: `docs/uml-classes.md` (пакеты Model / View / Controller).
